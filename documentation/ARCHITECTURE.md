# Архитектура

## Обзор

«Помоги роботу» — одностраничное React-приложение (SPA). Одна сборка
обслуживает хаб (меню глав) и все мини-игры; каждая глава книги
[robot-talks](../../robot-talks) (кроме первой и последней) соответствует
одной мини-игре.

Стек: Vite + React + TypeScript, Vitest + Testing Library (юнит/компонентные
тесты), Playwright (визуальные/e2e тесты). Инфраструктура (конфиги, скрипты,
принцип «сборка в `./docs`» для GitHub Pages) взята за образец с проекта
[formula-synth](../../formula-synth).

Бэкенда нет. Весь прогресс и настройки — в `localStorage`.

## Хаб и регистрация игр

`src/games/registry.ts` — единственное место, где перечисляются игры
(`GameDescriptor[]`). Хаб (`Hub.tsx`) и роутер ничего не знают о конкретных
играх — они работают с этим списком и с `Progress` из `progress/progress.ts`.
Чтобы добавить новую главу-игру, нужно:

1. Создать `src/games/game-NN-<slug>/` с компонентом, реализующим
   `GameProps` (`{ onComplete: () => void }`).
2. Добавить запись в `GAMES` в `registry.ts`.

Порядок в `GAMES` определяет и порядок прохождения: игра разблокируется,
когда предыдущая в списке отмечена как пройденная (`isGameUnlocked`).

## Прогресс

`progress/progress.ts` хранит `{ completedGameIds: string[]; introSeen:
boolean }` под ключом `robot-game:progress:v1` в `localStorage`. Функции
чистые и покрыты тестами (`tests/progress.test.ts`); повреждённые/чужеродные
данные в `localStorage` (включая объект без поля `introSeen`) трактуются как
пустой прогресс, а не бросают исключение.

## Роутинг

Самодельный хеш-роутер (`routing/useHashRoute.ts`) без внешних зависимостей:
`#/` — хаб, `#/game/<id>` — экран игры. Это осознанный выбор при таком
масштабе (десяток экранов) — react-router не нужен, а хеш-навигация не
требует серверных правил перезаписи на статическом GitHub Pages хостинге.

## Устройство мини-игры «Ремонтная консоль» (глава 01)

Подробности реализации — в
[documentation/features/game-01-repair-console.md](./features/game-01-repair-console.md).
Кратко: `shell/` — самостоятельный, не завязанный на React слой

## UX-паттерны, общие для всех будущих глав

Родились в рамках доработки главы 01 по итогам ревью — стоит переиспользовать
для игр 02–08, а не изобретать заново.

### Интро: два уровня

Не путать эти два попапа — у них разная область ответственности и разная
частота показа:

1. **Глобальный попап (`components/GlobalIntro.tsx`)** — один на весь сайт.
   Рассказывает общую завязку (мир после конца цивилизации, кто мальчик и
   робот, что игрок играет за мальчика, который учится программировать,
   чтобы помогать роботу) + ссылку на книгу
   (`https://dmitryweiner.github.io/robot-talks/`). Показывается
   **автоматически один раз** — при самом первом визите на сайт
   (`!progress.introSeen`, `App.tsx`), закрытие помечает `introSeen: true`
   через `markIntroSeen()`. Дальше — только по требованию, кнопкой
   «Введение» над списком глав в `Hub.tsx`.
2. **Попап главы (`StoryIntro.tsx` в папке каждой игры)** — свой на каждую
   мини-игру, показывается **при каждом входе** в неё (не только один раз).
   Не повторяет общие слова про мир/персонажей (это забота глобального
   попапа) — только: что случилось/что нужно сделать в этой конкретной
   главе, и какие средства у игрока есть (например, какие команды
   доступны, что есть кнопка-подсказка). Ссылку на книгу сюда не дублировать.

Оба используют общий `components/Modal.tsx`.

### Иллюстрация, отражающая прогресс

Небольшая анимированная иллюстрация сцены главы, поза/состояние которой —
чистая функция от прогресса игрока (по аналогии с `pose.ts`). Сейчас это
инлайн-SVG (см. предупреждение про `transform-origin` в feature-доке главы
01) — де-факто плейсхолдер до появления настоящих спрайтов.

### Кнопка-подсказка `(?)`

По требованию показывает точный ответ (что именно ввести/сделать) без
возможности скопировать текст (`style={{ userSelect: 'none' }}` + блокировка
`onCopy`/`onContextMenu`). Показывать только сам факт «что делать», прятать
до явного запроса игрока — подсказки в сайдбаре сами по себе не должны
спойлерить решение.

### Справочник команд («man») в сайдбаре

В левой панели — строка кликабельных ссылок `man <имя>` на каждую команду
(и отдельно — на каждый использованный shell-оператор, `|`, `>` и т. д.).
Клик открывает **один** попап `CommandReference` с man-страницей именно этой
команды (не общий список всех сразу — раньше был один комбинированный попап,
пользователь явно попросил сделать по ссылке на команду). Компоненты
переиспользуемые (`components/CommandReference.tsx` + `components/
ManLinks.tsx`), данные — свои на игру (`game-NN-*/manPages.ts`).

Заводя новую главу с новым набором команд, держи `manPages.ts`
синхронизированным с реальным списком команд движка (`COMMAND_NAMES`) — в
игре 1 это гарантируется тестом (`tests/shell/manPages.test.ts` проверяет
двустороннее соответствие: каждой существующей команде есть man-страница, и
наоборот). Копируй этот тест-инвариант для новых глав, а не полагайся на
память при добавлении команд.

## Тесты

- **Юнит/компонентные** (`tests/**/*.test.{ts,tsx}`, Vitest + Testing
  Library): вся логика без побочных эффектов (fs, parser, interpreter,
  progress, роутинг) и React-компоненты через `@testing-library/react`.
- **Визуальные/e2e** (`tests-e2e/**/*.spec.ts`, Playwright): реальный
  браузер, сборка через `npm run build` + `npm run preview` (см.
  `playwright.config.ts`).

Команда `npm run check` = `tsc --noEmit && eslint . && vitest run` — гонять
после каждой правки.

## Сборка и публикация

`vite build` собирает в `./docs` (не в `dist`) — так GitHub Pages может
отдавать сайт прямо из `docs/` на ветке `main` без дополнительных экшнов.
Эта папка коммитится в репозиторий (см. `.gitignore`).
