# Фича: Игра 1 — «Ремонтная консоль»

План — [documentation/plans/game-01-repair-console.md](../plans/game-01-repair-console.md).
Ниже — как это устроено на практике, после реализации.

## Что это

Виртуальная Unix-консоль в браузере. Игрок печатает настоящие shell-команды,
работает с выдуманной файловой системой робота `northbridge` и должен пройти
путь из главы: найти сбойный драйвер, прочитать журнал, обнаружить, что
скрипту `drivers/nb_init.sh` не хватает прав на исполнение, выдать их и
запустить скрипт.

## Виртуальная файловая система (`shell/fs.ts`)

Дерево `DirNode`/`FileNode` в памяти (не в localStorage — состояние игры не
сохраняется между визитами, каждый заход начинается с чистого стартового
дерева `createInitialFs()`). Все мутирующие операции (`writeFile`,
`setExecutable`) работают по схеме «склонировать (`structuredClone`) → изменить
клон → вернуть», а не мутируют аргумент — так React может держать `fs` в
`useState` и полагаться на неизменность для реактивности, и это же упрощает
тесты (`fs.test.ts` явно проверяет, что исходное дерево не трогается).

`globMatch` реализует раскрытие `*` только для последнего сегмента пути
(этого достаточно для `drivers/nb_*` из главы) — конвертирует шаблон в regex
через экранирование спецсимволов вокруг `*`.

## Разбор команды (`shell/parser.ts`)

Ручной токенайзер (без regex-стейт-машины): понимает двойные кавычки
(`echo "два слова"` → один токен), операторы `2>&1`, `>>`, `2>`, `>`, `<`,
`|` как отдельные токены даже без пробелов вокруг. Токены пайплайна
разбиваются по `|`, внутри каждого сегмента редиректы вычленяются в список
`Redirection[]`, оставшиеся слова — это `name` + `args`. Синтаксическая
ошибка (повисший редирект, пустой сегмент пайпа) не бросает исключение, а
возвращает `{ commands: [], error: string }` — интерпретатор превращает это
в обычную строку в stderr терминала.

## Выполнение (`shell/interpreter.ts`)

`execLine(line, state)` — единственная точка входа. По порядку:

1. `cd` как единственная команда в строке обрабатывается отдельно
   (`execCd`) — она меняет `cwd`, а не печатает поток данных, и в пайплайне
   не участвует (в главе `cd` вообще не используется).
2. Для остальных пайплайнов: на каждую команду раскрываются `*`-глобы
   (`expandGlobs`), затем если есть `<` — стдин берётся из файла вместо
   потока от предыдущей команды в пайпе.
3. Команда выполняется через `runCommand` (диспетчер по имени + отдельная
   ветка «это путь к файлу» для `./drivers/nb_init.sh`).
4. Редиректы применяются в порядке: `2>&1` (слияние в stdout) → `2>` (стдерр
   в файл) → `>`/`>>` (стдаут в файл). Если команда не последняя в пайпе и
   её stdout не был перенаправлен в файл — он становится стдином следующей.
5. Событие `ShellEvent` (пока единственный вариант — `script-success`)
   всплывает наружу нетронутым — на нём завязано условие победы.

Каждая команда в `commands.ts` — чистая функция `(args, stdin, fs, ctx) =>
CommandResult`, без доступа к React. `chmod` — единственная «обычная»
команда, которая возвращает изменённый `fs` в `CommandResult.fs`.

### Почему `wc -l` даёт правильный ответ

`echo` всегда добавляет завершающий `\n` (как настоящий echo). Подсчёт строк
в `wc -l` — это подсчёт символов `\n` в содержимом (`(content.match(/\n/g) ??
[]).length`), а не количество элементов после `split('\n')` — это в точности
поведение настоящего `wc -l`, и поэтому `echo "проверка" > f; wc -l < f` даёт
`1`, как в тексте главы.

## Подсказки без гейтинга (`objectives.ts`)

`detectStageIndex(line, result)` — чистая эвристика: смотрит на текст только
что введённой команды и на её вывод, и возвращает индекс «сюжетного шага»,
которому это действие соответствует (или `null`). `RepairConsoleGame`
хранит `stageIndex` и двигает его только вперёд
(`Math.max(prev, detected + 1)`). Игрок может пропустить шаги — например,
сразу набрать `chmod +x …` и `./drivers/nb_init.sh`, ни разу не заглянув в
журнал — игра это не запрещает. Условие победы полностью независимо от
`stageIndex`: это событие `script-success` от интерпретатора при успешном
запуске `/drivers/nb_init.sh`.

## Terminal.tsx

Держит `ShellState` в `useState`, рендерит scrollback (список введённых
команд + строк вывода) и однострочный `<input>`. История команд — обычный
массив строк, `ArrowUp`/`ArrowDown` бегают по нему как в настоящем shell.
Автоскролл вниз через `useEffect` на `scrollTop = scrollHeight` (не
`scrollTo`, которого нет в jsdom — иначе юнит-тесты падали с
`scrollTo is not a function`).

`Tab` вызывает `completeInput` (`shell/complete.ts`) и всегда делает
`event.preventDefault()` — иначе браузер уводит фокус на следующий
фокусируемый элемент страницы (эту правку попросил пользователь отдельно,
после первого прохождения игры — «жму Tab, а браузер перехватывает»).
`completeInput` — чистая функция: для первого слова без `/` матчит по
`COMMAND_NAMES` (экспортируется из `commands.ts`), иначе резолвит директорию
последнего слова через `fs.ts` и матчит по именам файлов/папок в ней.
Дополняет только при **однозначном** совпадении (директории — с `/` и без
пробела, чтобы можно было дополнять дальше; команды и файлы — с пробелом
после). Неоднозначность или отсутствие совпадений — просто no-op, без
вывода списка вариантов (сознательное упрощение).

## Попап-интро, иллюстрация и подсказка-кнопка (добавлено по ревью)

Три доработки поверх исходной версии, все — по прямому запросу пользователя
после первого прохождения игры:

- **`StoryIntro.tsx`** — показывается при каждом входе в игру поверх общего
  `components/Modal.tsx` (переиспользуемый диалог: оверлей, `role="dialog"`,
  закрытие по клику на фон/крестик/кнопку). `RepairConsoleGame` держит
  `introDismissed` и не рендерит терминал, пока интро не закрыто кнопкой
  «Начать».

  Изначально здесь же были общие слова про мальчика/робота/книгу — по
  повторному ревью пользователь попросил их убрать: общая завязка мира
  переехала в **`components/GlobalIntro.tsx`**, показывается один раз на
  весь сайт (см. `documentation/ARCHITECTURE.md` → «Интро: два уровня»).
  `StoryIntro.tsx` теперь содержит **только специфику главы**: что случилось
  и что нужно сделать (сломанный северный мост, драйвер не запустился) +
  какие средства доступны игроку (команды консоли + кнопка-подсказка).
  Ссылки на книгу тут больше нет — она уже была показана в `GlobalIntro`.
  **Это общий паттерн для будущих глав**: `Modal` переиспользуй, а
  `StoryIntro`-контент каждой главы пиши только про задачу этой главы, без
  повторения общей завязки.
- **`RobotIllustration.tsx` + `pose.ts`** — маленький инлайн-SVG (рамки-примитивы,
  не спрайты — см. «Известные упрощения» ниже), поза выбирается чистой
  функцией `poseForProgress(stageIndex, solved): 'lying' | 'lifting' |
  'fixed'`. Поворот всей фигуры делается CSS-transform (`rotate` вокруг
  `transform-origin: 0 0`, а не координат `translate`!
  **Грабли, на которые уже наступили**: если `transform-origin` поставить
  равным точке `translate()` из того же свойства `transform`, поворот
  происходит вокруг уже смещённой точки и уносит фигуру далеко за пределы
  `viewBox` — фигура визуально пропадает. Если будешь чинить/трогать эту
  анимацию — сначала прочитай этот абзац, потом код.) Глаз мигает всегда
  (CSS `@keyframes`), шестерня «скрежещет» (`animation: robot-grind`) только
  в позе `lying`, гаснет в `lifting`/`fixed`.
- **`HintButton.tsx`** — кнопка `(?)` рядом с текстовой подсказкой,
  раскрывает точную команду для текущей стадии (`STAGES[i].command`, добавлено
  в `objectives.ts`). Текст команды рендерится с `style={{ userSelect: 'none'
  }}` и `onCopy`/`onContextMenu` c `preventDefault` — это защита «на
  добросовестного пользователя» (от случайного Ctrl+C/выделения), а не
  DRM: скриншот или чтение DOM всё равно работают, и это осознанно
  приемлемо для игры. Сброс `revealed` при смене стадии сделан **не** через
  `useEffect`+`setState` (это словит `react-hooks/set-state-in-effect` от
  eslint), а через передачу `key={stage.id}` в `RepairConsoleGame` —
  React сам размонтирует/пересоздаёт компонент на новой стадии.

## Справочник команд (`manPages.ts` + `CommandReference.tsx` + `ManLinks.tsx`)

Добавлено по ещё одной просьбе пользователя: «в левой панели ссылку на man
page используемых команд» — и уточнение сразу же после первой реализации:
**«ссылки» во множественном числе**, команд-то несколько. Первая версия
делала одну ссылку, открывающую попап сразу со всеми командами; переделано
на **по ссылке на каждую команду и оператор**, каждая открывает свой
собственный попап (как настоящий `man <имя>` показывает одну страницу).

- `manPages.ts` — данные: `COMMAND_MAN_PAGES: Record<string, ManPageEntry>`
  (ключ — имя команды, значение обязано существовать для каждого имени из
  `COMMAND_NAMES` — это отдельно проверяется тестом, см. ниже) и
  `OPERATOR_MAN_PAGES: ManPageEntry[]` для `|`, `>`, `>>`, `<`, `2>`, `2>&1`,
  `./`. Тексты описывают **нашу** реализацию, а не полный POSIX-набор флагов
  — например, у `grep` явно сказано «обычная подстрока, не регулярное
  выражение», у `ls` — что есть только `-l` и `*`-подстановка.
- `components/CommandReference.tsx` (переиспользуемый, не завязан на игру
  1) — попап на одну `ManPageEntry`: заголовок `man <name>`, `<code>` с
  синопсисом, абзац описания. Тип `ManPageEntry` объявлен прямо здесь и
  реэкспортирован из `manPages.ts` — общий компонент владеет контрактом
  данных, а не наоборот.
- `components/ManLinks.tsx` (тоже переиспользуемый) — рендерит подпись
  (`label`) и ряд кликабельных ссылок, `onSelect(entry)` вызывается с той
  `ManPageEntry`, на которую кликнули. `RepairConsoleGame` держит один
  `manEntry: ManPageEntry | null` и рендерит `CommandReference` только когда
  он не `null` — то есть в моменте открыт максимум один man-попап.
- `tests/shell/manPages.test.ts` держит инвариант в обе стороны: у каждой
  команды из `COMMAND_NAMES` есть страница, и в данных нет страниц на
  несуществующие команды. **Копируй этот тест-паттерн для будущих глав** —
  дешёвый способ не забыть задокументировать новую команду движка.

## Известные упрощения (см. также план)

- Размер файла в `ls -l` — это `content.length` (UTF-16 code units), не
  байты. Для учебной консоли этого достаточно.
- `grep` матчит только литеральную подстроку, без regex/флагов.
- Только один «настоящий» исполняемый скрипт в дереве (`nb_init.sh`) — любой
  другой исполняемый файл при запуске молча завершится успешно без вывода;
  это ветка на будущее, сейчас недостижима из стартового состояния.
- **Иллюстрация робота — это грубый inline SVG (прямоугольники/круги),
  а не спрайты**, хотя в `INITIAL.md` заявлен спрайтовый 2D-стиль. Решение
  прагматичное: у агента нет инструментов генерации пиксель-арта в этой
  сессии. Если/когда появятся настоящие спрайты (кадры PNG) — `pose.ts`
  (чистая функция стадия→поза) можно оставить как есть и просто заменить
  `RobotIllustration.tsx` на переключение кадров спрайт-листа по тому же
  `pose`, ничего в игровой логике менять не придётся.
- Tab-автодополнение раскрывает только команды и пути (файлы/папки), не
  флаги команд (`ls -` не подскажет `-l`).
